# 引脚与调试

**本项目文件由 AI 协助整理，可能存在遗漏或错误，请在使用、加工或制作前自行审核并核对相关内容。**

下表记录的是 PCB 上 Pico 焊盘连接的网络名。它是硬件连线，不等于 GP2040-CE 网页中当前保存的功能；刷机或恢复配置后应重新按表核对。

## 推荐配置顺序

1. 在 GP2040-CE 的 **引脚映射**页，先让每一个实体键在网页输入测试或 Windows 中有正确反应。
2. `GP2/W` 与 `GP15/W2` 是两个不同的物理引脚；若两颗键都要作为跳键，就都选择逻辑 **Up/上**。
3. 其他按键按实际用途映射。`GP22` 是额外实体键，可以映射为一个未占用的普通手柄键，再在游戏里单独绑定；不要把它误当作固件自动生成的“迸发”功能。
4. 游戏输入正确后，再单独处理 RGB 按键顺序与 OLED 布局。不要为了修灯光错位而改动已验证正确的方向键 GPIO。

## RGB 灯光错位：按此顺序排查

按键功能、灯珠物理串接顺序、网页中的“RGB LED 按钮顺序”是三套独立关系。灯按错位置通常不是开关焊错，而是后三者没有对应好。

1. 先关闭复杂动画，使用单色或按键反馈，逐颗确认实际亮起的物理位置。
2. 在 **RGB LED 按钮顺序** 中把按键名称拖成与真实灯带数据流一致的顺序，而不是按照手柄功能或面板视觉排列。
3. 保存、重启后逐颗按实体键验证；每次只改一个位置，记录“按键 → 实际灯珠”。
4. 两个跳键可都映射为逻辑“上”，但主题/按键反馈通常只有一个 `Up` 灯位，因而第二个跳键不一定能自动拥有独立灯光反馈。若要求它独立点亮，需要把对应实体键作为一个独立的普通手柄键使用并在游戏内绑定，或接受它与 `Up` 共用反馈。
5. 宏输出的是一组逻辑输入，并不会自动得到独立的 RGB 按键灯位。希望“一个实体键、一个游戏功能、一个灯位”时，应优先使用普通手柄按键映射而不是宏。

## USB：22 Ω / 0805 电阻

PCB 上有两只 R0805，分别串在 `LS ↔ LS_USB` 与 `RS ↔ RS_USB`，对应 `GP27`、`GP26` 到 USB-A 的两条数据通路。采购规格为 **22 Ω、0805**：前者是阻值，后者是封装尺寸。PCB 版图本身不保存阻值文本；若改 USB 接法或重做板，请根据所用 USB Host 电路、数据手册和实物重新确认，不要只凭封装下单。

## OLED 与输入模式

- OLED 使用 I²C：`GP0/SDA`、`GP1/SCL`；供电和屏幕地址也需和模块一致。
- 屏幕上的按钮示意只影响显示，不改变实体按键接线。本机实测左右两侧均选 `Stickless 16` 更接近面板布局。
- PC 上使用 XInput 时，Windows/Steam 可能显示为 Xbox 360 控制器。PS5 兼容与认证另受 GP2040-CE 的认证方案和外设影响，PCB 本身不能保证即插即用。

## 复测清单

按 **实体键 → GP2040-CE 输入测试 → Windows/Steam → 游戏内 → RGB → OLED** 的顺序复测。这样能区分是开关/GPIO、固件映射、游戏设置，还是灯光与显示布局的问题。
